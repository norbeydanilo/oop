# Modificadores de Acceso en Java
## Guía práctica con paquetes en VS Code

> En esta guía aprenderás qué son los modificadores de acceso, por qué existen y cómo se comportan usando paquetes — la forma en que Java organiza las clases en un proyecto real.

---

## 1. ¿Qué es un modificador de acceso?

Un **modificador de acceso** es una palabra reservada que controla desde dónde puede ser visto o usado un atributo, método o clase.

Ya conoces dos: `private` y `public`. Pero Java tiene cuatro en total:

| Modificador | Nombre informal |
|---|---|
| `private` | Privado |
| *(ninguno)* | Friendly o de paquete |
| `protected` | Protegido |
| `public` | Público |

Para entender la diferencia entre ellos, primero necesitas entender qué es un **paquete**.

---

## 2. ¿Qué es un paquete?

Un **paquete** (`package`) es una carpeta que agrupa clases relacionadas. Es la forma en que Java organiza proyectos grandes para que no todo quede en un mismo lugar.

Piénsalo como una carpeta de archivos:

```
src/
└── com/
    └── universidad/
        ├── banco/
        │   ├── Cuenta.java
        │   └── Banco.java
        └── cliente/
            └── App.java
```

- `Cuenta` y `Banco` están en el paquete `com.universidad.banco`
- `App` está en el paquete `com.universidad.cliente`
- Son **paquetes diferentes** — como carpetas diferentes

Para declarar en qué paquete está una clase, la primera línea del archivo debe ser:

```java
package com.universidad.banco;
```

---

## 3. Los cuatro modificadores explicados

### `private` — Solo yo

Solo puede accederse desde **dentro de la misma clase**. Nadie más, ni siquiera otra clase del mismo paquete.

```java
package com.universidad.banco;

public class Cuenta {
    private double saldo; // solo Cuenta puede tocarlo

    public double getSaldo() {
        return saldo; // esto sí es válido — estamos dentro de Cuenta
    }
}
```

```java
package com.universidad.banco;

public class Banco {
    public void mostrar(Cuenta c) {
        // System.out.println(c.saldo); ← ERROR: saldo es private
        System.out.println(c.getSaldo()); // correcto: usamos el getter
    }
}
```

**Regla:** los atributos siempre `private`. Los getters y setters hacen de porteros.

---

### Sin modificador — Friendly (de paquete)

Si no escribes ningún modificador, el acceso es **friendly**: visible para todas las clases del **mismo paquete**, pero invisible desde otros paquetes.

```java
package com.universidad.banco;

public class Cuenta {
    double saldo; // sin modificador = friendly
}
```

```java
package com.universidad.banco;

public class Banco {
    public void mostrar(Cuenta c) {
        System.out.println(c.saldo); // OK — mismo paquete
    }
}
```

```java
package com.universidad.cliente;

import com.universidad.banco.Cuenta;

public class App {
    public static void main(String[] args) {
        Cuenta c = new Cuenta();
        // System.out.println(c.saldo); ← ERROR: paquete diferente
    }
}
```

**Cuándo usarlo:** poco recomendado — es un acceso "accidental". Prefiere `private` con getters.

---

### `protected` — Familia y paquete

Visible para:
- Todas las clases del **mismo paquete**
- **Subclases** (clases hijas), aunque estén en otro paquete

```java
package com.universidad.banco;

public class Cuenta {
    protected double saldo; // visible para subclases
    protected String titular;

    public Cuenta(String titular, double saldo) {
        this.titular = titular;
        this.saldo   = saldo;
    }
}
```

```java
package com.universidad.cliente;

import com.universidad.banco.Cuenta;

public class CuentaVIP extends Cuenta {

    public CuentaVIP(String titular, double saldo) {
        super(titular, saldo);
    }

    public void mostrarInfo() {
        // Puede acceder porque hereda de Cuenta
        System.out.println("Titular: " + titular);
        System.out.println("Saldo: " + saldo);
    }
}
```

```java
package com.universidad.cliente;

import com.universidad.banco.Cuenta;

public class App {
    public static void main(String[] args) {
        Cuenta c = new Cuenta("Ana", 100000);
        // System.out.println(c.saldo); ← ERROR: App no es subclase de Cuenta
        // Solo CuentaVIP puede acceder porque hereda
    }
}
```

**Cuándo usarlo:** cuando diseñas clases pensadas para ser extendidas (superclases), y quieres que las subclases puedan acceder a ciertos atributos directamente.

---

### `public` — Todos

Visible desde cualquier clase, en cualquier paquete.

```java
package com.universidad.banco;

public class Cuenta {
    private double saldo;

    public double getSaldo() { // visible para todos
        return saldo;
    }

    public void depositar(double monto) { // visible para todos
        if (monto > 0) saldo += monto;
    }
}
```

```java
package com.universidad.cliente;

import com.universidad.banco.Cuenta;

public class App {
    public static void main(String[] args) {
        Cuenta c = new Cuenta();
        c.depositar(50000);                  // OK — public
        System.out.println(c.getSaldo());    // OK — public
    }
}
```

**Regla:** los métodos que forman la "interfaz pública" del objeto van `public`.

## 5. Crea el proyecto en VS Code

### Paso 1 — Instala la extensión

Abre VS Code → Extensions (Ctrl+Shift+X) → busca **Extension Pack for Java** de Microsoft → instalar.

### Paso 2 — Crea el proyecto

1. Abre la paleta de comandos: `Ctrl+Shift+P`
2. Escribe: `Java: Create Java Project`
3. Selecciona **No build tools**
4. Elige la carpeta donde quieres guardar el proyecto
5. Nombre del proyecto: `ModificadoresAcceso`

VS Code crea esta estructura automáticamente:

```
ModificadoresAcceso/
├── src/
│   └── App.java
└── README.md
```

### Paso 3 — Crea los paquetes (carpetas)

Dentro de `src/` crea estas carpetas manualmente o desde VS Code:

```
src/
├── banco/
│   ├── Cuenta.java
│   └── Banco.java
└── cliente/
    └── App.java
```

Para crear desde VS Code: clic derecho sobre `src/` → **New Folder** → escribe `banco`. Repite para `cliente`.

### Paso 4 — Crea los archivos

**`src/banco/Cuenta.java`**
```java
package banco;

public class Cuenta {

    private   String titular;    // solo Cuenta
    double    saldo;             // friendly: banco y Cuenta
    protected String tipo;       // banco, Cuenta y subclases
    public    String numeroCuenta; // todos

    public Cuenta(String titular, double saldo, String tipo, String numero) {
        this.titular      = titular;
        this.saldo        = saldo;
        this.tipo         = tipo;
        this.numeroCuenta = numero;
    }

    // Getter para acceder al atributo private desde fuera
    public String getTitular() {
        return titular;
    }

    public double getSaldo() {
        return saldo;
    }

    public void depositar(double monto) {
        if (monto > 0) {
            saldo += monto;
            System.out.println("Deposito de " + monto + " realizado.");
        }
    }

    public void mostrarInfo() {
        System.out.println("Titular: " + titular);        // private: OK (estamos dentro)
        System.out.println("Saldo: " + saldo);            // friendly: OK
        System.out.println("Tipo: " + tipo);              // protected: OK
        System.out.println("Numero: " + numeroCuenta);    // public: OK
    }
}
```

**`src/banco/Banco.java`**
```java
package banco;

public class Banco {

    public void operar(Cuenta c) {
        // private titular → ERROR si descomentamos:
        // System.out.println(c.titular);

        System.out.println(c.saldo);        // friendly: OK (mismo paquete)
        System.out.println(c.tipo);         // protected: OK (mismo paquete)
        System.out.println(c.numeroCuenta); // public: OK

        // Para acceder a titular usamos el getter:
        System.out.println(c.getTitular());
    }
}
```

**`src/cliente/CuentaVIP.java`**
```java
package cliente;

import banco.Cuenta;

public class CuentaVIP extends Cuenta {

    private double limiteCredito;

    public CuentaVIP(String titular, double saldo, double limite) {
        super(titular, saldo, "VIP", "VIP-001");
        this.limiteCredito = limite;
    }

    public void mostrarInfoVIP() {
        // private titular → NO accesible (otro paquete, no importa que sea subclase)
        // System.out.println(titular); ← ERROR

        // friendly saldo → NO accesible (otro paquete)
        // System.out.println(saldo); ← ERROR

        // protected tipo → SÍ accesible (subclase)
        System.out.println("Tipo: " + tipo);

        // public numeroCuenta → SÍ accesible (todos)
        System.out.println("Numero: " + numeroCuenta);

        // Getter para acceder al private:
        System.out.println("Titular: " + getTitular());

        System.out.println("Limite de credito: " + limiteCredito);
    }
}
```

**`src/cliente/App.java`**
```java
package cliente;

import banco.Cuenta;
import banco.Banco;

public class App {
    public static void main(String[] args) {

        Cuenta c = new Cuenta("Ana Torres", 500000, "Ahorros", "AH-001");

        // private → ERROR:
        // System.out.println(c.titular);

        // friendly → ERROR (paquete diferente):
        // System.out.println(c.saldo);

        // protected → ERROR (no es subclase):
        // System.out.println(c.tipo);

        // public → OK:
        System.out.println(c.numeroCuenta);

        // Getters (public) → OK para todo:
        System.out.println(c.getTitular());
        System.out.println(c.getSaldo());

        c.depositar(100000);
        c.mostrarInfo();

        System.out.println("---");

        // CuentaVIP hereda de Cuenta y accede a protected
        CuentaVIP vip = new CuentaVIP("Carlos Rios", 2000000, 500000);
        vip.mostrarInfoVIP();

        System.out.println("---");

        // Banco está en el mismo paquete que Cuenta
        Banco banco = new Banco();
        banco.operar(c);
    }
}
```

### Paso 5 — Ejecuta

Abre `App.java` → clic en **Run** (triángulo verde arriba a la derecha) o presiona `F5`.

Verás en la consola los valores que sí pueden accederse y podrás descomentar las líneas con `ERROR` para ver cómo el compilador las rechaza.

---

## 6. Regla de oro para tus clases

```
atributos  → private   (nadie los toca directamente)
getters    → public    (para leer)
setters    → public    (para modificar con control)
constructor → public   (para crear objetos)
métodos de comportamiento → public (interfaz del objeto)
```

`protected` se reserva para cuando diseñas una jerarquía de herencia y necesitas que las subclases accedan a ciertos atributos sin exponerlos a todos.

`friendly` casi nunca se usa intencionalmente — si ves un atributo sin modificador, probablemente fue un olvido.
