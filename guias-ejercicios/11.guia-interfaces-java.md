# Interfaces en Java
## Guía práctica con proyecto en VS Code

> En esta guía aprenderás qué es una interfaz, para qué sirve y cómo implementarla. Las interfaces son uno de los mecanismos más poderosos de Java para lograr abstracción y polimorfismo sin depender de la herencia.

---

## 1. ¿Qué es una interfaz?

Una **interfaz** es un contrato. Define **qué** debe hacer una clase, pero no **cómo** lo hace.

Imagina un control remoto: no importa si el televisor es Samsung o LG, el control tiene los mismos botones — encender, apagar, subir volumen. El contrato es el mismo; cada televisor lo implementa a su manera.

En Java:
- Una **interfaz** declara los métodos (el contrato)
- Una **clase** los **implementa** (el cómo)

```java
// El contrato: cualquier cosa que sea "encendible" debe poder encenderse y apagarse
public interface Encendible {
    void encender();
    void apagar();
}
```

```java
// Television implementa el contrato a su manera
public class Television implements Encendible {
    public void encender() {
        System.out.println("Televisor encendido. Cargando canales...");
    }
    public void apagar() {
        System.out.println("Televisor apagado.");
    }
}
```

```java
// Lampara también implementa el mismo contrato, diferente comportamiento
public class Lampara implements Encendible {
    public void encender() {
        System.out.println("Lampara encendida. Luz al 100%.");
    }
    public void apagar() {
        System.out.println("Lampara apagada.");
    }
}
```

## 2. Diferencias entre interfaz y clase abstracta

|  | Interfaz | Clase abstracta |
|---|---|---|
| Palabra clave | `interface` | `abstract class` |
| Cómo se usa | `implements` | `extends` |
| ¿Cuántas puede usar una clase a la vez? | Muchas (`implements A, B, C`) | Solo una (`extends UnaClase`) |
| ¿Se puede instanciar directamente? | No | No — solo se puede heredar |
| Puede tener atributos de instancia | No (solo constantes `static final`) | Sí |
| Puede tener constructores | No | Sí |
| Métodos con cuerpo | Solo con `default` o `static` | Sí |
| Para qué sirve | Definir un contrato de comportamiento | Compartir código entre clases relacionadas |

**Regla práctica:**
- Usa una **interfaz** cuando quieres definir *qué puede hacer* algo, sin importar qué *es*
- Usa **herencia** cuando quieres compartir código entre cosas que *son* del mismo tipo

## 3. Reglas de las interfaces

```java
public interface MiInterfaz {

    // 1. Los métodos son public abstract por defecto (no hace falta escribirlo)
    void metodo1();
    void metodo2(String param);

    // 2. Las constantes son public static final por defecto
    int MAX = 100; // equivale a: public static final int MAX = 100;

    // 3. Desde Java 8: métodos con implementación por defecto
    default void saludar() {
        System.out.println("Hola desde la interfaz");
    }

    // 4. Desde Java 8: métodos estáticos
    static void info() {
        System.out.println("Soy una interfaz");
    }
}
```

**Lo más importante:** si una clase implementa una interfaz, **debe** implementar todos sus métodos abstractos — o declararse `abstract`.

## 4. Una clase puede implementar varias interfaces

Esta es la gran ventaja sobre la herencia: Java no permite herencia múltiple de clases, pero sí de interfaces.

```java
public interface Volador {
    void volar();
}

public interface Nadador {
    void nadar();
}

public interface Corredor {
    void correr();
}

// Pato puede volar, nadar y correr
public class Pato implements Volador, Nadador, Corredor {
    public void volar()  { System.out.println("Pato volando..."); }
    public void nadar()  { System.out.println("Pato nadando..."); }
    public void correr() { System.out.println("Pato corriendo..."); }
}

// Aguila solo vuela y corre
public class Aguila implements Volador, Corredor {
    public void volar()  { System.out.println("Aguila volando alto..."); }
    public void correr() { System.out.println("Aguila corriendo..."); }
}
```

## 5. Polimorfismo con interfaces

La variable puede ser del tipo de la interfaz — no importa qué clase concreta haya detrás.

```java
Encendible dispositivo;

dispositivo = new Television();
dispositivo.encender(); // "Televisor encendido. Cargando canales..."

dispositivo = new Lampara();
dispositivo.encender(); // "Lampara encendida. Luz al 100%."
```

Esto permite escribir código que funciona para cualquier implementación — presente o futura:

```java
public void apagarTodo(Encendible[] dispositivos) {
    for (Encendible d : dispositivos) {
        d.apagar(); // no importa qué clase es, sabemos que tiene apagar()
    }
}
```

## 6. Crea el proyecto en VS Code

### Estructura del proyecto

```
InterfacesJava/
└── src/
    ├── contratos/
    │   ├── Pagable.java
    │   ├── Notificable.java
    │   └── Reportable.java
    └── empleados/
        ├── Empleado.java
        ├── EmpleadoTiempoCompleto.java
        ├── EmpleadoPorHoras.java
        └── App.java
```

**Contexto:** un sistema de empleados donde diferentes tipos de empleados se pagan de forma distinta, se notifican diferente y generan reportes diferentes.

---

### Paso 1 — Crea el proyecto

1. `Ctrl+Shift+P` → `Java: Create Java Project` → **No build tools**
2. Nombre: `InterfacesJava`
3. Dentro de `src/` crea las carpetas `contratos` y `empleados`

---

### Paso 2 — Crea las interfaces

**`src/contratos/Pagable.java`**
```java
package contratos;

public interface Pagable {
    // Contrato: cualquier empleado debe poder calcular su pago
    double calcularPago();

    // Constante disponible para todas las implementaciones
    double SALARIO_MINIMO = 1300000.0;

    // Método default: comportamiento base que las clases pueden sobreescribir
    default String obtenerDetallePago() {
        return "Pago calculado: $" + calcularPago();
    }
}
```

**`src/contratos/Notificable.java`**
```java
package contratos;

public interface Notificable {
    // Contrato: cualquier empleado debe poder ser notificado
    void notificar(String mensaje);
    String obtenerContacto();
}
```

**`src/contratos/Reportable.java`**
```java
package contratos;

public interface Reportable {
    // Contrato: cualquier empleado debe poder generar un reporte
    String generarReporte();
}
```

### Paso 3 — Crea la clase base

**`src/empleados/Empleado.java`**
```java
package empleados;

public class Empleado {
    private String nombre;
    private String id;
    private String cargo;

    public Empleado(String nombre, String id, String cargo) {
        this.nombre = nombre;
        this.id     = id;
        this.cargo  = cargo;
    }

    public String getNombre() { return nombre; }
    public String getId()     { return id; }
    public String getCargo()  { return cargo; }
}
```

### Paso 4 — Implementa las interfaces

**`src/empleados/EmpleadoTiempoCompleto.java`**

Implementa las tres interfaces: `Pagable`, `Notificable` y `Reportable`.

```java
package empleados;

import contratos.Pagable;
import contratos.Notificable;
import contratos.Reportable;

public class EmpleadoTiempoCompleto extends Empleado
        implements Pagable, Notificable, Reportable {

    private double salarioMensual;
    private String correo;

    public EmpleadoTiempoCompleto(String nombre, String id,
                                   String cargo, double salario, String correo) {
        super(nombre, id, cargo);
        this.salarioMensual = salario;
        this.correo         = correo;
    }

    // ── Implementación de Pagable ──────────────────────────
    @Override
    public double calcularPago() {
        return salarioMensual;
    }

    // Sobreescribe el método default de Pagable
    @Override
    public String obtenerDetallePago() {
        return "Empleado tiempo completo | Salario fijo: $" + salarioMensual;
    }

    // ── Implementación de Notificable ──────────────────────
    @Override
    public void notificar(String mensaje) {
        System.out.println("Correo a " + correo + ": " + mensaje);
    }

    @Override
    public String obtenerContacto() {
        return correo;
    }

    // ── Implementación de Reportable ──────────────────────
    @Override
    public String generarReporte() {
        return "=== REPORTE ===" +
               "\nNombre: "  + getNombre() +
               "\nID: "      + getId() +
               "\nCargo: "   + getCargo() +
               "\nTipo: Tiempo completo" +
               "\nPago: $"   + calcularPago();
    }
}
```

**`src/empleados/EmpleadoPorHoras.java`**

Solo implementa `Pagable` y `Notificable` — no genera reportes.

```java
package empleados;

import contratos.Pagable;
import contratos.Notificable;

public class EmpleadoPorHoras extends Empleado
        implements Pagable, Notificable {

    private double valorHora;
    private int    horasTrabajadas;
    private String telefono;

    public EmpleadoPorHoras(String nombre, String id, String cargo,
                             double valorHora, int horas, String telefono) {
        super(nombre, id, cargo);
        this.valorHora       = valorHora;
        this.horasTrabajadas = horas;
        this.telefono        = telefono;
    }

    // ── Implementación de Pagable ──────────────────────────
    @Override
    public double calcularPago() {
        return valorHora * horasTrabajadas;
    }

    // ── Implementación de Notificable ──────────────────────
    @Override
    public void notificar(String mensaje) {
        System.out.println("SMS a " + telefono + ": " + mensaje);
    }

    @Override
    public String obtenerContacto() {
        return telefono;
    }
}
```

### Paso 5 — Usa las interfaces en App

**`src/empleados/App.java`**
```java
package empleados;

import contratos.Pagable;
import contratos.Notificable;
import contratos.Reportable;

public class App {
    public static void main(String[] args) {

        // Crear empleados
        EmpleadoTiempoCompleto emp1 = new EmpleadoTiempoCompleto(
            "Ana Torres", "E001", "Desarrolladora", 4500000, "ana@empresa.com"
        );
        EmpleadoPorHoras emp2 = new EmpleadoPorHoras(
            "Carlos Rios", "E002", "Consultor", 50000, 80, "300-1234567"
        );

        System.out.println("=== PAGOS ===");

        // Polimorfismo: variable de tipo Pagable, distintas implementaciones
        Pagable[] pagables = { emp1, emp2 };
        for (Pagable p : pagables) {
            System.out.println(p.obtenerDetallePago());
        }

        System.out.println("\n=== NOTIFICACIONES ===");

        // Polimorfismo: variable de tipo Notificable
        Notificable[] notificables = { emp1, emp2 };
        for (Notificable n : notificables) {
            n.notificar("Su pago ha sido procesado.");
        }

        System.out.println("\n=== REPORTES ===");

        // Solo emp1 implementa Reportable
        // Verificamos con instanceof antes de hacer el cast
        Empleado[] empleados = { emp1, emp2 };
        for (Empleado e : empleados) {
            if (e instanceof Reportable) {
                Reportable r = (Reportable) e;
                System.out.println(r.generarReporte());
            } else {
                System.out.println(e.getNombre() + " no genera reporte.");
            }
        }

        System.out.println("\n=== CONSTANTE DE INTERFAZ ===");
        System.out.println("Salario minimo: $" + Pagable.SALARIO_MINIMO);

        System.out.println("\n=== VERIFICAR CONTRATOS ===");
        // Una clase puede verificar qué interfaces implementa en tiempo de ejecución
        System.out.println("emp1 es Pagable:    " + (emp1 instanceof Pagable));
        System.out.println("emp1 es Reportable: " + (emp1 instanceof Reportable));
        System.out.println("emp2 es Pagable:    " + (emp2 instanceof Pagable));
        System.out.println("emp2 es Reportable: " + (emp2 instanceof Reportable));
    }
}
```

**Salida esperada:**
```

Pago calculado: $4000000.0

=== NOTIFICACIONES ===
Correo a ana@empresa.com: Su pago ha sido procesado.
SMS a 300-1234567: Su pago ha sido procesado.

=== REPORTES ===
=== REPORTE ===
Nombre: Ana Torres
ID: E001
Cargo: Desarrolladora
Tipo: Tiempo completo
Pago: $4500000.0
Carlos Rios no genera reporte.

=== CONSTANTE DE INTERFAZ ===
Salario minimo: $1300000.0

=== VERIFICAR CONTRATOS ===
emp1 es Pagable:    true
emp1 es Reportable: true
emp2 es Pagable:    true
emp2 es Reportable: false
```

## 7. Puntos clave para recordar

| Concepto | Detalle |
|---|---|
| `interface` | Define el contrato (qué, no cómo) |
| `implements` | La clase se compromete a cumplir el contrato |
| `@Override` | Indica que se está implementando un método de la interfaz |
| Múltiples interfaces | Una clase puede implementar varias: `implements A, B, C` |
| Variable de interfaz | `Pagable p = new EmpleadoTiempoCompleto(...)` — polimorfismo |
| `instanceof` | Verifica si un objeto cumple un contrato en tiempo de ejecución |
| `default` | Método con implementación base en la interfaz (Java 8+) |

---

## 8. ¿Cuándo usar una interfaz?

Usa una interfaz cuando:

- Quieres garantizar que varias clases **sin relación de herencia** compartan un comportamiento
- Diseñas un sistema extensible — las nuevas clases simplemente implementan el contrato
- Quieres aprovechar el **polimorfismo** sin forzar una jerarquía de herencia

```
Pagable ←── EmpleadoTiempoCompleto
Pagable ←── EmpleadoPorHoras
Pagable ←── Proveedor          (una clase completamente diferente)
Pagable ←── ClienteFacturado   (otra clase diferente)
```

Todas pueden pagar, ninguna necesita heredar de la misma superclase.
